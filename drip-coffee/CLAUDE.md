## 프로젝트: 핸드드립 추출 분석·추천 도구

핸드드립을 즐기는 사람이 새 원두를 처음 쓸 때 레시피를 맞추느라 여러 번 내려보며 원두를 낭비하는 과정을 줄이는 도구.

- 기능 1 분쇄도 측정: 축척 용지(모서리 마커) 위에 펼친 원두 가루 사진 → 입자 검출 → 마이크론 단위 크기 분포와 미분 비율
- 기능 2 추출 예측·추천: 원두 정보, 원두·물 양, 물 온도, 붓는 시점과 양, 분쇄도 → 농도(TDS), 추출수율(EY), 물 빠짐 시간 예측. 목표 TDS·EY에 맞는 레시피를 역으로 계산해 추천
- 기능 3 기록·보정: 실제 추출의 음료 무게, 물 빠짐 시간, 맛 6항목(Aroma, Flavor, Acidity, Body, Balance, Aftertaste)을 기록하고 예측과 비교해 계수를 보정. 보정에는 음료 무게와 물 빠짐 시간만 쓰고, 맛 점수는 기록·참고용

## 제약

- 외부 AI·LLM API를 쓰지 않는다. 계산은 모두 코드 안에서 한다. 외부 데이터 연결은 허용.
- 측정 도구는 저울(0.1g), 타이머, 카메라뿐이다. 굴절계가 없어서 TDS·EY는 직접 잴 수 없다. TDS·EY 예측은 논문 실험 데이터로 검증하고, 실측 기록은 물 빠짐 시간과 음료 무게 보정에만 쓴다.
- 추출 모델의 식과 상수는 문헌에 근거한다. 모든 상수는 `docs/MODEL.md` 표에 값, 단위, 출처, 상태(미확인/확인/가정)를 적고, 출처 없는 숫자는 쓰지 않는다. 에이전트가 제시한 인용은 사용자가 원문과 대조하기 전까지 '미확인'이다.
- 공개 도구나 논문의 코드는 복사하지 않는다. 방법만 참고하고 출처를 밝힌다.
- 장비: 하리오 V60, V60 NEO, 홀츠클로츠 메버릭1 그라인더(집), 0.1g 저울, 온도 조절 주전자. 평소 레시피는 정인성 4666, 484.
- 추출은 본가에서 목요일 저녁~일요일 점심에만 가능하다. 추출 과정은 영상으로 녹화하고, 시간 값은 영상에서 읽는다. 영상과 원본 사진은 커밋하지 않는다.

## 기술과 구조

- Python 3.12 + Streamlit, numpy/scipy/pandas, OpenCV(opencv-python-headless).
- 계산 모듈은 화면과 분리된 순수 함수로 짜고 pytest로 검증한다. 핵심 로직은 5개 파일(분쇄 분석, 추출 모델, 보정, 추천, 앱 화면)에만 둔다.
- 저장소 경로에 한글이 있어 `cv2.imread`/`cv2.imwrite`가 실패할 수 있다. 이미지 입출력은 바이트 기반으로 한다(`np.fromfile` + `cv2.imdecode`, `cv2.imencode` + `tofile`).
- 앱이 쓰는 작업 데이터는 `data/local/`(커밋 안 함)에 둔다.
- 실행(이 폴더에서): `python -m venv .venv` → `.venv\Scripts\python -m pip install -r requirements.txt` → `.venv\Scripts\streamlit run app.py`. 테스트는 `.venv\Scripts\python -m pytest`.

## 작업 방식

- 단계를 시작하기 전에 커밋 단위 계획을 먼저 보여주고 승인받는다.
- 커밋 하나에 의미 있는 변경 하나. 메시지는 한국어로, 제목은 무엇을 바꿨는지, 본문은 왜·무엇·확인.
- 커밋마다 바뀐 파일과 메시지를 보여주고 사용자 확인을 받은 뒤 커밋·푸시한다.
- 이미 푸시한 커밋은 고치지 않는다(amend, force push 금지). 잘못은 fix 커밋으로 바로잡는다. 날짜 조작, 빈 커밋, 개수 채우기용 커밋은 만들지 않는다.
- 범위나 일정을 바꾸면 그 이유를 WORKLOG에 남긴다.
- 결정, 문제, 대응은 `docs/WORKLOG.md`에 관련 커밋과 함께 남긴다. 지난 일을 나중에 적으면 작성 날짜를 표시한다.
- 핵심 함수는 짧은 설명을 함께 주고, 사용자가 이해한 뒤 커밋한다.

## 과제 규칙

- 코드는 이 프로젝트를 위해 새로 작성한다. 예전 과제, 튜토리얼 저장소, 다운로드한 템플릿 코드를 가져오지 않는다. 일반적인 프레임워크와 라이브러리는 사용해도 된다.
- API 키, 비밀번호, 개인정보, 의존성 폴더, 빌드 결과물, 큰 원본 데이터, 영상 파일은 커밋하지 않는다.
- README.md는 1,200단어 이하. 이미지와 에이전트 발췌는 합쳐서 최대 6개, 핵심 소스 파일은 최대 5개.
- README 초안을 도와줄 수는 있지만, 에이전트 출력을 그대로 붙여넣지 않고 사용자가 읽고 고칠 수 있는 형태로 쓴다.
