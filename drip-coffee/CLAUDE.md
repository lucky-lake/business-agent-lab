## 프로젝트: 드립 AR 바리스타

드립커피 추출 게임. 플레이어(나)는 1인칭 시점으로 카페 바 카운터를 따라 이동하며 손님 주문에 맞는 커피를 내린다. Claude는 AR 코치로 화면에 떠서 조언한다.

- 핵심 흐름: 주문 → 원두 선택 → 분쇄(분쇄도 다이얼, 핸들 3바퀴 돌리면 이후 자동) → 붓기(커서 위치 = 물줄기 위치, Space 누르는 동안 붓기) → 시음·별점
- 이동: A/D·방향키·트랙패드 스와이프로 카운터 좌우 이동, 장비를 클릭하거나 Space로 클로즈업. 구석에 AR 미니맵.
- 그래픽: 전부 실사풍. Canvas 2D에 코드로 그린다(외부 이미지·스프라이트를 내려받아 쓰지 않음). AR 요소(HUD, 도트 Claude)는 청록 톤.
- 기술: HTML + JS(ES 모듈) + Canvas 2D. Node·빌드 도구 없음. 로컬 실행은 `python -m http.server`, 배포는 GitHub Pages.
- 구조 원칙: 추출 계산(모델)과 그리기(렌더링)를 분리한다. 모델은 화면 없이도 테스트할 수 있는 순수 함수로 만든다.

## 일정과 범위

| 기간 | 목표 |
| ---- | ---- |
| ~9/29 | 게임 뼈대: 카운터 이동, 스테이션 상호작용, 화면 전환 |
| ~10/6 | 붓기 미니게임: 마우스 붓기, 균일도 격자, 추출 계산 |
| ~10/13 | 원두 선택·분쇄 미니게임을 계산에 연결, 시음·별점 |
| ~10/20 | 손님 주문, Claude 코치, 그래픽 다듬기 |
| ~11/1 | 기능 동결. 검증, README, 영상 |

핵심 흐름(원두 → 분쇄 → 붓기 → 결과)이 최우선이다. 일정이 밀리면 손님 다양화, 장식, 부가 연출부터 뺀다.

## 작업 방식

- 한 번에 크게 만들지 않는다. 한 단계씩 제안하고, 사용자가 확인하면 진행한다.
- 단계가 끝나면 무엇이 바뀌었는지 짧게 요약하고 커밋 메시지를 제안한다. 커밋은 사용자 확인 후에.
- 의미 있는 결정, 문제와 해결 과정은 `docs/WORKLOG.md` 에 기록하도록 알려준다.

## 과제 규칙

- 코드는 이 프로젝트를 위해 새로 작성한다. 예전 과제, 튜토리얼 저장소, 다운로드한 템플릿 코드를 가져오지 않는다. 일반적인 프레임워크와 라이브러리는 사용해도 된다.
- API 키, 비밀번호, 개인정보, 의존성 폴더, 빌드 결과물, 큰 원본 데이터, 영상 파일은 커밋하지 않는다.
- README.md 는 1,200단어 이하. 에이전트 발췌/스크린샷은 최대 6개, 핵심 소스 파일은 최대 5개.
- README 초안을 도와줄 수는 있지만, 에이전트 출력을 그대로 붙여넣지 않고 사용자가 읽고 고칠 수 있는 형태로 쓴다.
