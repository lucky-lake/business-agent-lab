# Drip Coffee-오늘의 한 잔: 핸드드립 추출 분석·추천 도구

원두 분쇄도를 사진 분석으로 µm 단위까지 재고, 문헌을 바탕으로 만든 추출 모델로 처음 쓰는 원두에도 괜찮은 첫 잔 레시피를 추천합니다. 맛 기록이 쌓일수록 추천 기준이 내 입맛에 맞춰 바뀝니다.

- **배포 주소:** https://drip-coffee.streamlit.app/ (첫 화면의 '만든 사람 기록 둘러보기'를 누르면 실제로 내린 기록으로 바로 추천을 받아 볼 수 있습니다)

## 목적과 사용자

사용해보지 않은 원두를 사면 맞는 레시피를 찾느라 분쇄, 온도, 물 양을 바꿔 가며 몇 잔을 맛없게 마시게 됩니다. 이 도구는 저울, 타이머, 휴대폰 정도만 가진 사람이 이 시행착오 없이 새 원두를 즐길 수 있도록 돕습니다.

처음 목표는 "한 번에 완벽한 잔"이었습니다. 하지만 좋은 잔의 기준은 사람마다 다르고, 굴절계 없이는 맛을 수치로 확인할 수 없으며, 같은 원두도 다른 날 산 봉투면 물 빠짐 예측이 ±20초쯤 어긋납니다. 그래서 목표를 "괜찮은 첫 잔, 그다음부터는 잔마다 내 입맛으로"로 다시 정했습니다.

**범위:** 외부 AI API는 쓰지 않고 계산은 모두 코드 안에서 합니다. 농도와 추출수율은 재지 않고 모델로 추정하며, 붓는 방식(센터·원형)은 사용자에게 맡깁니다.

## 주요 기능

1. **분쇄도 측정:** 축척 용지 위에 펼친 원두 가루 사진에서 입자 크기를 µm로 잽니다.
2. **레시피 추천:** 물 양, 온도, 붓기 일정, 분쇄, 가수량을 추천하고, 갈고 나서 잰 크기에 맞춰 붓기 간격과 가수량을 다시 맞춥니다.
3. **입맛 학습:** 맛 점수와 진하기 답으로 추천 목표를 골든컵에서 내 입맛 쪽으로 옮깁니다.

## 사용법

준비물은 0.1 g 저울, 타이머, 휴대폰 카메라, A4에 실제 크기(100%)로 인쇄한 축척 용지입니다.

앱에서 '한 잔 내리기'를 누르면 원두와 장비 → 기초 추천 → 분쇄 확인(사진) → 내리기와 기록 → 맛 평가 → 마무리 순서로 안내합니다. 배포한 앱은 기록을 그 기기의 브라우저에만 저장하고, 다른 기기로는 기록 파일(zip)로 옮깁니다. 앱이 잠들어 있으면 'Yes, get this app back up!'을 누르고 30초쯤 기다려 주세요.

## 설치와 실행

Python 3.12 이상(윈도우 3.12, 우분투 3.14에서 확인)과 `requirements.txt`의 패키지가 필요합니다.

```bash
git clone https://github.com/lucky-lake/business-agent-lab.git
cd business-agent-lab/drip-coffee
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

- 테스트: `python -m pytest`
- 축척 용지 만들기: `python tools/make_scale_sheet.py` → `out/scale_sheet_v1.pdf`

## 검증

- **자동 테스트:** pytest 193개가 분쇄 측정, 모델, 기록, 추천, 앱 화면을 확인합니다.
- **분쇄 측정:** 크기를 아는 합성 입자로 지름 오차 2% 이내를 확인했습니다.
- **추출 모델:** 문헌 실험 데이터 14항목 중 13항목을 통과했습니다. 긴 추출의 시간 효과만 맞지 않아, 추천을 물 빠짐 2:00–3:30 안으로 제한했습니다.
- **처음 보는 원두 시험 (10/28):** 모델을 고정한 뒤 아껴 둔 원두 4잔을 미리 정한 기준(물 빠짐 ±30초, 음료 ±6 g, 만족도 3.0 이상, 4잔 중 3잔)으로 판정했습니다. 물 빠짐 4/4, 음료 3/4, 만족도 4/4로 세 항목 모두 통과했습니다.
- **실패 사례:** 음료 무게는 처음 보는 원두 6잔 모두 예측이 3–9 g 많았고, 그중 3잔은 기준을 넘었습니다. 기준은 바꾸지 않고 한계로 적었습니다.

잔별 숫자는 [MODEL.md](docs/MODEL.md)에, 예외 상황 8가지는 [WORKLOG 검증 기록](docs/WORKLOG.md#검증-기록)에 있습니다.

## 회고

### 좋았던 방법

1. **결과를 보기 전에 판정 기준을 커밋했습니다.** 보정에서 오차가 더 작은 값이 나왔을 때도, 케냐 잔이 음료 기준을 0.04 g 넘었을 때도 미리 정한 기준대로 판정했습니다.
2. **화면은 HTML 시안부터 비교했습니다.** 에이전트에게 시안 여러 개를 만들게 해 고른 뒤 앱에 넣어, 다시 만드는 일이 줄었습니다.
3. **CLAUDE.md에 규칙을 적고 커밋 단위로 확인했습니다.** 커밋마다 바뀐 파일과 메시지를 보고 승인해, 에이전트가 한 일을 놓치지 않았습니다.

### 어려웠던 점

1. **에이전트의 잘못된 추측:** 주제를 정할 때 Claude가 다운로드 폴더의 파일명으로 제 관심사를 추측했습니다. 관심사는 직접 말하고 파일로 추측하지 않도록 정했습니다.
2. **에이전트가 가져온 숫자:** 논문 인용이 그럴듯해도 틀릴 수 있었습니다. 모델에 쓴 숫자 8편을 원문과 하나씩 대조했고, 확인 전까지는 '미확인'으로 두었습니다.
3. **그럴듯한 설명:** 에이전트가 결과의 원인을 잘못 설명한 적이 있습니다(케냐 잔의 분쇄가 목표에 가까웠던 이유). 다시 계산하게 해 바로잡았지만, 모든 설명을 검산하기는 어려워 남은 문제입니다.

## 한계와 다음 할 일

- 농도와 추출수율은 모델 추정값입니다. V60 문헌 데이터에서는 추출수율을 약 2%p 낮게 봅니다.
- 음료 무게는 원두마다 가루가 머금는 물이 달라 많게 예측됩니다.
- 오래 우릴 때의 쓴맛(시간 효과), 막힘, 붓는 방식은 계산하지 못합니다.
- 넓게 맞붙은 입자는 크게 잽니다.
- 맛 점수는 한 사람이 블라인드 없이 매긴 값입니다.
- **다음 할 일:** 원두별로 가루가 머금는 물을 따로 맞춰 음료 무게 오차를 줄이는 것입니다.

## 구조와 구현

계산은 화면과 분리된 함수로 짜서 pytest로 확인하고, 핵심 로직은 아래 5개 파일에만 둡니다. 기록은 `data/`의 CSV 파일로 저장합니다.

- [`dripcoffee/grind_analysis.py`](dripcoffee/grind_analysis.py) **분쇄 사진 분석** (OpenCV, SciPy): 축척 용지의 ArUco 마커를 찾아 호모그래피로 사진을 정면으로 펴고 픽셀당 µm를 구합니다. 조명을 고르게 맞춘 뒤 입자를 찾고, 붙은 입자는 거리 변환으로 잘록한 곳에서 나누며, 엉킨 덩어리와 은피는 모양과 색으로 뺍니다. 분포 곡선은 gaussian_kde로 그립니다.
- [`dripcoffee/extraction_model.py`](dripcoffee/extraction_model.py) **추출 모델** (NumPy, 식은 직접 구현): 0.5초 간격으로 다르시 법칙에 따른 흐름, 크기 구간별 두 갈래 추출(표면 성분과 입자 속 성분), 가루가 머금는 물을 계산합니다.
- [`dripcoffee/calibration.py`](dripcoffee/calibration.py) **기록과 보정:** 기록을 읽고 쓰며 예측과 비교하고(계수 맞추기는 `tools/calibrate.py`), 내 사진 기록으로 그라인더 클릭 힌트를 줍니다.
- [`dripcoffee/recommend.py`](dripcoffee/recommend.py) **추천:** 좋았던 잔의 중심에 골든컵을 '5잔 분량'으로 섞어 목표를 정하고, 물 양 × 붓기 나누기 × 온도의 후보를 모두 모델로 계산해 목표에 가장 가까운 레시피를 고릅니다.
- [`app.py`](app.py) **화면** (Streamlit, Altair): '한 잔 내리기', 내 기록, 모델 점검 화면입니다. 배포 버전은 기록을 브라우저에 저장하고 zip으로 옮깁니다.

축척 용지는 matplotlib과 OpenCV로 만들고(`tools/make_scale_sheet.py`), 모델의 식과 상수 출처는 [MODEL.md](docs/MODEL.md)에 있습니다.
