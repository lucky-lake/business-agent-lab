# Drip Coffee: 핸드드립 추출 분석·추천 도구

원두 가루 사진으로 분쇄도를 µm 단위로 재고, 문헌 기반 추출 모델로 물 빠짐 시간, 음료 무게, 농도, 추출수율을 예측해 처음 쓰는 원두에도 괜찮은 첫 잔 레시피를 추천합니다. 맛을 기록할수록 추천 목표가 내 입맛 쪽으로 옮겨 갑니다. 외부 AI API 없이 계산은 모두 코드 안에서 합니다.

## Purpose and Intended User

새 원두를 열면 분쇄, 온도, 물 양을 바꿔 가며 몇 잔을 버리게 됩니다. 이 도구는 저울(0.1 g), 타이머, 폰 카메라만 있는 홈 바리스타가 그 시행착오를 줄이도록 돕습니다.

처음 목표는 "한 번에 완벽한 잔"이었습니다. 하지만 완벽한 첫 잔은 모델이 충분히 정확하고 내 입맛 기록이 쌓여야 가능합니다. 좋은 잔의 기준은 사람마다 다르고(제가 좋았던 잔들은 모델 추정으로 골든컵 범위보다 덜 우러난 쪽에 모였습니다), 굴절계 없이는 맛을 숫자로 확인할 수 없으며, 봉투가 바뀌면 물 빠짐 예측이 ±20초쯤 어긋납니다. 그래서 입맛은 잔마다, 레시피는 원두마다 맞춰지는 구조에 집중했습니다.

- **첫 잔:** 문헌 기반 모델과 지금까지의 기록(내 장비에 맞춘 계수, 같은 배전도 원두의 평소 레시피, 내 사진과 클릭표의 비율)으로 낼 수 있는 최선의 레시피를 추천합니다. 처음 보는 케냐 원두 두 잔은 첫 잔부터 만족도 4.13, 4.00이었습니다.
- **다음 잔부터:** 맛 점수와 진하기 답으로 목표가 내 입맛 쪽으로 옮겨 갑니다(모든 원두의 잔을 함께 씁니다). 같은 원두를 다시 내리면 그 원두의 지난 잔이 평소 레시피가 되고, 같은 봉투를 잰 기록으로 클릭 힌트가 정확해집니다. 물리 계산은 고정해 두었습니다.

### 무엇이 다른가

1. **분쇄를 µm로 잽니다.** 축척 용지의 ArUco 마커로 비스듬한 사진을 펴고 알갱이마다 지름을 잽니다. 크기를 아는 합성 입자로 지름 오차 2% 이내를 확인했고, 분석 화면에서 단계마다 쓴 방법과 출처(직접 확인한 8개)를 보여 줍니다.
2. **간 가루에 맞춰 레시피를 다시 맞춥니다.** 갈고 나서 사진으로 잰 크기에 맞춰 붓기 간격(±15초)과 가수량을 다시 계산합니다. 검증 잔(B06)은 가루가 목표보다 26% 굵게 나와 간격을 30초에서 45초로 늘렸고, 만족도는 4.13점이었습니다.
3. **내 장비에 맞춰집니다.** 모델 계수 두 개(흐름 저항, 가루가 머금는 물)는 제 잔 7잔으로 맞췄습니다. 클릭 힌트는 내 사진이 클릭표보다 약 1.29배 굵게 나오는 것을 반영하고 막혔던 클릭은 피합니다.
4. **내 입맛을 목표로 삼습니다.** 맛 6항목 중 만족도 4항목으로 좋았던 잔일수록 목표를 세게 당기고, 진하기는 한 번 물어 목표 농도에 바로 반영합니다. 기록이 적을 때는 골든컵을 '좋았던 잔 5잔 분량'으로 섞습니다.
5. **기준을 먼저 정하고 그대로 보고합니다.** 상수마다 값, 출처, 상태를 [`docs/MODEL.md`](docs/MODEL.md) 표에 적었고, 모델에 쓴 논문 숫자 8편은 원문과 대조했습니다. 문헌 비교, 보정 규칙, 검증·시험 기준은 결과를 보기 전에 커밋했습니다(`5d1570e`, `570b8aa`, `6e85182`, `6c5a3c4`). 기준을 0.04 g 넘은 잔도 불통과로 적었습니다.

## How to Run

웹에서는 위 주소로 바로 씁니다. 앱이 잠들어 있으면 'Yes, get this app back up!'을 누르고 30초쯤 기다려 주세요. 배포한 앱은 기록을 서버에 남기지 않고 그 기기의 브라우저에만 저장하며, 다른 기기로는 기록 파일(zip)로 옮깁니다.

내 컴퓨터에서는 Python 3.12 기준으로 `drip-coffee/` 폴더에서 실행합니다.

```bash
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

- 테스트: `python -m pytest`
- 축척 용지: `python tools/make_scale_sheet.py`로 만든 `out/scale_sheet_v1.pdf`를 A4 실제 크기(100%)로 인쇄합니다.

## Work Process

자세한 기록은 [`docs/WORKLOG.md`](docs/WORKLOG.md)에 있습니다.

1. **주제 (9/23–10/6):** 게임을 기획했다가 친구 피드백과 고민 끝에 추출 분석·추천 도구로 바꿨습니다. 관점이 다른 계획 네 개를 비교해 실행 계획을 정했습니다.
2. **분쇄 사진 분석 (10/8–10/12):** 정확도 테스트를 먼저 쓰고 구현했습니다. 실제 사진에서 생긴 문제(가려진 마커, 은피, 붙은 입자)는 테스트로 재현하며 고쳤습니다.
3. **추출 모델 (10/12–10/15):** 조사 노트를 쓰고 식 12개로 모델을 만들었습니다.
4. **교수님 피드백 (10/15):** "사진을 올려 AI에 묻는 것 이상의 개성"을 고민해, 추천 목표를 골든컵에서 '내 선호 영역'으로 옮기게 했습니다.
5. **보정 (10/16–10/19):** 제 잔 7잔으로 계수 두 개를 맞췄습니다. 처음 규칙에 빠졌던 '문헌 비교 유지' 조건은 새 기록으로 다시 맞추기 전에 더했고(`570b8aa`), 오차가 더 작은 값 대신 규칙대로 골랐습니다.
6. **앱 (10/19–10/24):** 원두와 장비 → 기초 추천 → 분쇄 확인 → 내리기 → 맛 평가 → 마무리의 '한 잔 내리기' 흐름을 만들었습니다. "고급 메모장 같다"는 의견을 받고, 추천이 평소와 무엇이 다른지와 분쇄·온도를 바꿔 보는 계산을 넣었습니다.
7. **검증, 동결, 시험 (10/20–10/28):** 처음 보는 케냐 원두 두 잔으로 검증한 뒤 10/23에 모델을 고정했고(태그 `model-freeze`), 시험 원두 4잔으로 판정했습니다.
8. **배포 (10/24–10/26):** 방문자마다 기록을 따로 쓰고 기기에 저장하며 파일로 옮길 수 있게 했습니다.

- **분쇄 측정:** 합성 입자로 지름 오차 2% 이내. 비스듬히 찍은 사진도 점 크기 3%, 위치 0.2 mm 안으로 복원합니다. 실제 사진의 분포 폭(1.36–1.55)은 모델이 가정한 1.5와 맞았습니다.
- **추출 모델:** 문헌 실험 데이터 14항목 중 13항목을 통과했습니다. 긴 추출의 시간 효과만 불통과라 추천을 끊김 2:00–3:30 안으로 제한했습니다.

## Reflection

<!-- 초안: 직접 읽고 내 말로 고친다. -->

### Three Effective Practices

1. **결과를 보기 전에 판정 규칙을 정했습니다.** 보정에서 오차가 더 작은 값(n = 0)이 나왔을 때도 미리 정한 규칙대로 n = 2를 지킬 수 있었습니다.
2. **화면은 시안부터 만들었습니다.** HTML 시안 여러 개를 비교해 고른 뒤에 앱에 넣어서, 다시 만드는 일이 줄었습니다.
3. **커밋 단위로 계획하고 확인했습니다.** CLAUDE.md에 규칙을 적어 두고, 커밋마다 내용을 확인한 뒤 올렸습니다.

### Three Difficulties

1. **굴절계 없이 농도와 추출수율 검증하기:** 문헌 실험 데이터와 비교하고, 실제 기록은 시간과 무게에만 썼습니다.
2. **실제 사진에서 틀리는 분쇄 측정:** 붙은 입자와 은피를 잘라 모아 눈으로 확인하며 규칙을 고쳤습니다. 넓게 맞붙은 사슬은 남은 한계입니다.
3. **에이전트의 잘못된 추측:** 주제를 정할 때 Claude가 다운로드 폴더의 파일명으로 제 관심사를 추측했습니다. 관심사는 직접 말하고 파일로 추측하지 않도록 정했습니다.

## Known Limitations

- 농도와 추출수율은 모델 추정값입니다. V60 문헌 데이터에서는 추출수율을 약 2%p 낮게 봅니다.
- 음료 무게는 원두마다 가루가 머금는 물이 달라 빗나갈 수 있습니다(처음 보는 원두 6잔 모두 예측이 3–9 g 많았습니다).
- 오래 우릴 때 생기는 쓴맛(시간 효과), 막힘, 붓는 방식(센터·원형)은 계산하지 못합니다. 그래서 끊김을 제한하고, 막혔던 크기보다 굵게만 추천합니다.
- 넓게 맞붙은 입자는 크게 재집니다(가루를 듬성듬성 펴 달라고 안내합니다).
- 맛 점수는 한 사람이 블라인드 없이 매긴 값입니다.
- 배포한 앱의 기록은 그 기기의 브라우저에만 있습니다.
