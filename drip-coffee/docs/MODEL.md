# 추출 모델 설계 (초안, 2026-10-12)

레시피와 분쇄도로 **물 빠짐 시간, 음료 무게, 농도(TDS), 추출수율(EY)**을 예측하는 모델의 설계다.
식과 상수의 근거는 `docs/research/`의 조사 노트 1–4에 있다. 노트 번호는 `노트1 F2`처럼 적는다.

**상태 표시**
- **미확인:** 문헌에서 가져왔지만 사용자가 아직 원문과 대조하지 않음
- **확인:** 사용자가 원문과 대조함
- **가정:** 문헌에 직접 값이 없어 정한 값. 이유를 함께 적는다.
- **측정:** 우리가 직접 잰 값
- **보정:** 우리 추출 기록에 맞춰 정하는 값

## 1. 무엇을 넣고 무엇이 나오나

| 구분 | 항목 |
| ---- | ---- |
| 입력 | 원두 무게, 붓기 일정(`시작초:g;...`), 주전자 물 온도, 분쇄 측정(앱에 저장한 크기 분포), 가수량 |
| 출력 | 물 빠짐 종료 시각(물줄기가 끊기는 순간), 음료 무게(가수 전), 추출수율, 가수 전·후 농도 |
| 보정 (우리 기록) | 흐름 저항 계수, 가루가 머금는 물 비율. 각각 물 빠짐 시각과 음료 무게에 맞춘다 |
| 검증 (문헌) | 농도와 추출수율. 굴절계가 없어서 문헌 실험값과 비교한다 (노트4) |
| 추천 (9절) | 목표(골든컵에서 시작해 내 선호 영역으로) → 분쇄 대표 크기(µm), 온도, 가수량 |

## 2. 계산 순서

0.5초 간격으로 시간을 진행하며 아래를 반복한다.

1. **물 붓기:** 붓기 일정대로 드리퍼에 물이 들어온다. 한 번 붓는 동안의 붓는 속도는 입력값이다.
2. **물 흐름:** 드리퍼 안 물에서 가루가 머금는 양을 뺀 나머지가 가루층 위에 고인다. 고인 물의 높이에 따라 아래로 흘러나간다.
3. **추출:** 크기 구간마다 녹아 나온 양을 계산해 드리퍼 안 물에 더한다.
4. **음료:** 흘러나간 물이 그때의 농도만큼 녹은 성분을 함께 가지고 나간다.
5. **종료:** 마지막 붓기가 끝난 뒤 고인 물이 0이 되면 끝난다(물줄기가 끊기는 순간, 드리퍼를 뺌).

## 3. 식

### 3.1 물 흐름 (노트1)

드리퍼 안 액체 무게를 `M_L`, 가루가 머금는 물을 `H = R_abs × 원두 무게`라고 할 때:

```
고인 물      F = max(0, M_L − H)
가루층 부피   V_bed = 원두 무게 / ρ_bulk
물 표면 높이  z = [3·(V_bed + F/ρ + V_0) / (π·tan²α)]^(1/3) − h_0   (구멍 기준)       … (1)
잘린 꼭지     h_0 = r_구멍 / tanα,  V_0 = π·r_구멍²·h_0 / 3
흘러나가는 양 Q = ρ·g·z / (μ(T)·R)    (F > 0일 때만)                           … (2)
흐름 저항     R = R_ref · (d_ref / d)ⁿ · (원두 무게 / 20 g),  n = 2               … (3)
```

- 식 (2)는 다르시 법칙이다. 물 높이가 높을수록 빨리, 물이 차가울수록(점도가 클수록) 느리게 빠진다.
- 식 (3)의 `(d_ref/d)ⁿ`은 코제니–카르만 식의 '투과도 ∝ 입자 지름²'을 따라 n = 2로 둔다. d는 사진으로 잰 대표 크기(D50)이고, d_ref = 1000 µm이다. 보정에서 n을 바꿔 기록과 비교한다(5절).
- 식 (3)의 `원두 무게 / 20 g`은 다르시 법칙의 '저항 ∝ 층 길이'다. 물이 빠져나가는 면적은 드리퍼 아래쪽이 정한다고 보고, 원두가 늘면 가루층을 지나는 길이가 그만큼 길어진다고 둔다(가정). 처음 설계에는 이 항이 없었는데, 성질 테스트 ④(원두를 더 넣으면 늦게 빠짐)를 정하면서 빠진 것을 찾았다.
- R_ref는 **보정 계수 1**이다. 사진이 미분을 놓쳐 절대값 예측은 맞지 않기 때문이다(노트1 주의할 점).
- 종이 필터의 저항은 R_ref에 함께 들어간다. 기록을 보고 따로 떼야 하면 두 번째 계수로 나눈다.

### 3.2 추출 (노트2)

사진으로 잰 크기 구간 i(부피 비율 w_i, 지름 d_i)마다 계산한다. 사진에 안 잡히는 미분은 구간 하나로 따로 넣는다.

```
바로 나오는 비율   φ_i = 1 − (1 − 2δ/d_i)³          (입자 바깥 δ 두께 껍질의 부피 비율)   … (4)
느린 속도          k_i = k_ref · (r_ref / r_i)² · exp[−(Ea/R_gas)·(1/T − 1/T_ref)]           … (5)
녹아 나온 비율     X_i(t) = φ_i + (1 − φ_i)·(1 − e^(−k_i·t))                                 … (6)
녹아 나온 양       M_rel(t) = E_max · 원두 무게 · Σ w_i·X_i(t)                               … (7)
```

- t는 첫 물이 닿은 뒤(뜸 들이기부터) 지난 시간이다. 첫 붓기에서 가루가 모두 젖는다고 본다.
- 식 (5)의 1/r²는 입자 속 확산 시간이 크기의 제곱에 비례한다는 결과다(노트2 K2, K5). 카페인 측정에서도 10% 안쪽으로 맞았다.
- 드리퍼 안 물 온도 T는 `주전자 온도 − ΔT`로 둔다.

### 3.3 음료 (노트3)

```
드리퍼 안 녹은 성분   dS/dt = dM_rel/dt − Q·ρ·S/M_L                    … (8)
음료로 나간 성분     M_d = ∫ Q·ρ·S/M_L dt                              … (9)
음료 무게 (가수 전)   M_bev = ∫ Q·ρ dt                                  … (10)
추출수율             EY = M_d / 원두 무게                              … (11)
농도 (가수 전 / 후)   TDS = M_d / M_bev,   TDS_잔 = M_d / (M_bev + 가수량)   … (12)
```

- 드리퍼 안 물은 고루 섞여 있다고 본다. 가루가 머금은 물에도 같은 농도로 성분이 남아 버려진다.
- 식 (12): 가수는 추출수율을 바꾸지 않고 농도만 낮춘다.

## 5. 보정 (우리 기록 → 계수 2개)

- **R_ref:** `brews.csv`의 물 빠짐 종료 시각(`drawdown_end_s`)과 예측의 차이가 가장 작아지도록 정한다.
- **R_abs:** 음료 무게(`beverage_g`)와 예측의 차이가 가장 작아지도록 정한다.
- `표시`가 있는 잔(연습 등)은 빼고 쓴다.
- 필터 종이가 다른 잔(하리오 화이트, 홀츠클로츠 무표백)이 섞여 있다. 종이마다 흐름 저항이 다를 수 있으므로, 먼저 필터별로 예측 오차가 다른지 보고, 다르면 R_ref를 필터별로 맞춘다 (10/19).
- 보정 전후의 오차를 비교해 WORKLOG와 검증 문서에 남긴다.
- 기록이 적으면 한 잔을 빼고 나머지로 맞춘 뒤 뺀 잔을 예측해 본다(교차 확인).
- 방법(`tools/calibrate.py`, 10/19): R_ref는 끊김 시각 오차 제곱합, R_abs는 음료 무게 오차 제곱합이 가장 작아지게 번갈아 세 번 맞춘다. 분쇄 크기 지수 n(식 3)은 0, 0.5, 1, 1.5, 2를 비교해, 교차 확인의 끊김 오차(크기 평균)가 n = 2보다 2초 넘게 줄어드는 n이 있을 때만 바꾼다(결과를 보기 전에 정함).

**중간 결과 (10/19, 표시 없는 5잔)**

| | R_ref | R_abs | 끊김 (평균 · 크기 평균) | 음료 (평균 · 크기 평균) |
| ---- | ---- | ---- | ---- | ---- |
| 보정 전 (드리퍼 모양 반영 뒤) | 1.17×10¹² | 2.10 | +1.8초 · 13.8초 | +2.8 g · 3.0 g |
| 규칙대로 n = 0 | 7.96×10¹¹ | 2.24 | −2.6초 · 5.4초 | 0.0 g · 1.5 g |
| n = 2 그대로 | 1.04×10¹² | 2.24 | −6.2초 · 15.8초 | 0.0 g · 1.4 g |

- 교차 확인 끊김 크기 평균: n = 0 6.4초, 0.5 10.4초, 1 13.6초, 1.5 18.3초, 2 23.8초. 규칙대로면 n = 0(분쇄 크기가 물 빠짐에 영향이 없음)이다.
- 그런데 n을 줄이면 문헌 비교가 깨진다. 물 빠짐에 맞춰 크기를 찾는 ① V60 비교는 n = 2에서만 3회 모두 통과하고(추출수율 19.0–19.4%, 실험 20.8–21.2%), n = 1이면 3회 중 1회, n = 0.5면 3회 모두 불통과다. n = 0이면 ③(곱게 갈수록 물 빠짐이 늦어짐)도 통과할 수 없다. **미리 정한 규칙에 '6절의 문헌 판정을 계속 통과해야 한다'는 조건을 빠뜨렸다.**
- n이 작은 쪽을 가리키는 것은 대부분 20261018-1 한 잔(사진 1044 µm인데 2:15에 끝남) 때문이다. n = 2로 제곱 오차를 맞추면 이 잔에 끌려가 다른 4잔의 예측이 모두 짧아진다(크기 평균이 13.8 → 15.8초로 오히려 늘고, 음료는 3.0 → 1.4 g로 줄어든다).
- 필터별(n = 0 보정 뒤 끊김 평균): 하리오 화이트 −3.8초(3잔), 홀츠클로츠 무표백 −0.8초(2잔). 잔이 적어 따로 맞추지 않는다.
- 온도 의존 Ea를 키우면 B02 기준 레시피의 88 → 96 °C 추출수율 변화가 +0.6%p(17.3 kJ/mol) → +0.9%p(25) → +1.3%p(35)로 커진다(7절 한계).
- **결정:** 계수는 아직 바꾸지 않는다. n 규칙에 '6절 문헌 판정 유지'를 더하고, 10/19–20에 B02를 같은 봉투·같은 필터로 클릭만 바꿔(95, 105클릭) 사진과 함께 더 내린 뒤 보정을 다시 돌려 확정한다. 새 잔은 이 결정 뒤에 생기는 데이터라, 규칙을 결과를 보고 고친 문제를 줄인다.

## 6. 검증

### 원두를 세 묶음으로 나눈다 (학습 · 검증 · 시험, 10/15)

머신러닝에서 데이터를 학습·검증·시험으로 나누는 것처럼, 우리 원두도 쓰임을 나눈다. 모델이 '본 적 없는 원두'에서도 맞는지를 공정하게 보기 위해서다.

| 단계 | 원두 | 하는 일 | 고쳐도 되나 |
| ---- | ---- | ---- | ---- |
| **1. 학습 (보정)** | B02 너티 브리즈 (맛·보정 중심), B01 콜롬비아 디카페인 (흐름 실험) | 흐름 저항, 머금는 물 같은 계수를 이 기록에 맞춘다 | 자유롭게 |
| **2. 검증 (설계 결정)** | B06 케냐 캄왕기 AA (일반), B07 같은 생두의 미디움 다크 + 문헌 데이터 | 1단계 모델이 다른 원두와 다른 배전도에서도 맞는지 본다. 로스팅 정도 보정이나 뜸 항을 넣을지를 여기서 정한다 | 고치고 다시 확인 가능 |
| **3. 시험 (최종)** | B03 코스타리카 따라주, B05 브라질 다테하, B08 에티오피아 구지 우라가, 함께 받은 샘플 원두 (20–22 g, 한 잔씩) | 동결한 모델로 레시피를 추천받아 내리고, 예측과 실제를 비교한다 | **안 됨** |

3단계 규칙:
1. 시험 전에 모델을 고정한다 (기능 동결 뒤).
2. 판정 기준(물 빠짐·음료 무게 오차, 첫 잔 맛)을 시험 전에 정해 커밋한다.
3. 시험 원두로 미리 사진을 찍거나 연습으로 내리지 않는다. 샘플은 한 잔뿐이라 미리 볼 수 없어서 가장 깨끗한 시험 데이터다.
4. 결과가 나빠도 그대로 보고한다. 결과를 보고 모델을 고쳤다면 처음 결과를 공식 결과로 두고, 고친 뒤 결과는 따로 표시한다.

## 7. 알려진 한계

- 속도 상수는 카페인이나 다른 원두에서 왔다. V60, 강배전 값은 없다.
- 온도 영향의 근거가 약하다. 평형에서는 80–99 °C에서 거의 같았다(노트2 K8). 온도 의존(Ea 17.3 kJ/mol)은 물속 카페인 확산 값이다. 원문(노트2 K3)에 따르면 찻잎 안 확산은 물속보다 훨씬 방해받고, 원두 안은 찻잎보다는 덜 방해받는다. 그러니 원두 안의 값은 17.3보다 클 가능성이 높고, 모델이 온도 효과를 작게 볼 수 있다. 보정 단계에서 Ea를 키웠을 때 예측이 얼마나 달라지는지 확인한다 (10/19).
- 사진은 미분을 놓친다. 미분 비율 15%는 다른 그라인더의 값이다.
- 드리퍼 안 물을 고루 섞인 하나의 통으로 보고, 물길 쏠림(채널링)과 미분이 필터를 막는 현상은 넣지 않았다.
- **막힘을 예측하지 못한다.** B01 85클릭(1166 µm) 잔에서 미분이 필터를 막아 가루층 위에 물이 남은 채 물줄기가 줄었고, 드리퍼를 뺀 뒤에도 10.9 g이 더 나왔다. 모델은 이런 잔의 물 빠짐 시각과 음료 무게, 추출 위치를 실제와 다르게 계산한다. 대신 막힌 잔은 `막힘` 표시로 흐름 보정에서 빼고, 추천은 기록의 막힘 한계보다 굵게만 고른다(9.2).
- 원뿔 1차원 흐름은 근사다. 실제로는 종이 옆면으로도 물이 빠진다.
- 긴 추출(7분 이상)에서 시간을 늘린 효과를 작게 본다. 문헌 비교에서 실험 +3.4%p를 +0.3%p로 예측했다(6절). 입자 속 성분의 추출 속도를 하나로만 두기 때문이다.
- 아주 곱게 갈면 물 빠짐 시간을 너무 길게 예측한다(대표 크기 400 µm에서 15분 이상). 저항을 대표 크기의 제곱으로만 바꾸기 때문이다. 핸드드립 범위(약 800–1500 µm)는 85·105클릭 기록으로 확인한다.

## 9. 추천 (설계, 10/15)

교수님 피드백("범용 AI에게 사진을 올려 레시피를 묻는 것 이상의 개성이 무엇인가")에 대한 답으로, 추천 목표를 업계 평균(골든컵)이 아니라 **내 맛 기록에서 찾은 '내 선호 영역'**으로 옮겨 간다. 커피는 본질적으로 기호식품이라 '좋은 한 잔'의 기준이 사람마다 다르다. 골든컵은 많은 사람이 대체로 좋아하는 범위일 뿐, 나에게 맞는 목표는 아니다. 모델의 물리 계산은 그대로이고, 추천이 겨냥하는 목표 지점이 바뀐다.

### 9.1 목표 정하기

1. 기록한 잔마다 모델로 (추출수율, 가수 후 농도)를 계산한다. 이것이 그 잔의 위치다. 굴절계로 잰 값이 아니라 **모델 추정값**이라고 화면과 문서에 밝힌다.
2. 잔의 맛 점수 `s`는 만족도 4항목(Aroma, Flavor, Balance, Aftertaste)의 평균이다. 산미와 바디는 세기를 매긴 값이라 뺀다.
3. 내 선호 중심은 맛 점수로 가중한 평균 위치다. 가중치는 `w = max(s − 2.5, 0)`이라서, 보통(3점)보다 좋았던 잔일수록 중심을 세게 당기고 2.5점 이하인 잔은 당기지 않는다.
4. 추천 목표는 골든컵 중심과 섞는다. 기록이 적을 때는 골든컵에 가깝고, 쌓일수록 내 선호 쪽으로 옮겨 간다.

```
목표 = (n × 내 선호 중심 + 5 × 골든컵 중심) ÷ (n + 5)      n = 가중치가 0보다 큰 잔 수
```

| 값 | 내용 | 근거 | 상태 |
| ---- | ---- | ---- | ---- |
| 골든컵 중심 | 추출수율 20%, 농도 1.25% (골든컵 범위 18–22%, 1.15–1.35%의 가운데) | 노트3 M3 (SCA 기준 인용) | 미확인 |
| 섞는 비율 5 | 골든컵을 '좋았던 잔 5잔 분량'으로 친다 | 정한 값 | 가정 |
| 가중치 기준 2.5 | 이보다 낮은 점수의 잔은 중심을 당기지 않는다 | 정한 값 | 가정 |

- `표시`가 있는 잔(연습 등)과 맛 점수가 비어 있는 잔은 뺀다.
- 잔의 위치는 기록한 레시피(원두 무게, 온도, 붓기 일정, 가수량)와 분쇄 대표 크기로 **모델이 예측한 값만** 쓴다. 실제로 잰 물 빠짐 시각이나 음료 무게를 섞지 않는다. 추천(9.2)도 후보 레시피를 같은 모델로 계산해 목표와 비교하므로, 목표와 후보가 같은 기준 위에 있어야 하기 때문이다. 모델과 실제의 차이는 보정(5절)으로 줄인다 (10/18).
- 사진이 없는 잔은 같은 봉투(원두와 로스팅 날짜)·같은 그라인더·같은 클릭으로 간 다른 잔의 측정값 평균을 빌려 쓴다. 같은 원두라도 봉투가 바뀌면 같은 클릭에서 크기가 달라질 수 있다(10/18 B02 새 봉투: 1255 → 1044 µm). 표시가 있는 잔이어도 분쇄 측정은 맞으므로 빌려 줄 수 있다. 빌릴 값도 없으면 뺀다 (10/18).
- 처음에는 모든 원두의 기록을 합쳐 쓴다. 원두마다 선호가 크게 다르면 원두별로 나눌지는 검증 단계(6절)에서 정한다.

### 9.2 레시피 전체를 추천하기 (10/15 바로잡음)

제안서대로 **물 양, 물 온도, 붓기 일정(언제 몇 g), 분쇄, 가수량**을 모두 정하고, 예상 물 빠짐 시각까지 알려 준다. 원두 무게만 사용자가 정한다(기본 20 g). 처음에는 기본 붓기 일정을 그대로 두고 분쇄·온도·가수량만 바꾸도록 좁게 적었는데, 제안서의 '최적 레시피 제공'에 맞게 넓혔다.

1. **후보 만들기:** 아래 조합으로 후보 레시피를 만든다.

   | 정하는 것 | 후보 | 근거 |
   | ---- | ---- | ---- |
   | 전체 물 | 원두의 8–16배 (1배 간격) | 평소 레시피(1:8, 1:11에 가수)와 일반적인 핸드드립 비율을 함께 덮는 범위 (가정) |
   | 물 온도 | 배전도별 범위 안에서 1 °C 간격. 라이트 92–96, 미디엄 88–94, 다크(강배전) 80–88 °C. 원두 목록에 있는 중간 배전도는 미디엄 라이트 90–95, 미디엄 다크 84–90 °C (10/19) | 일반적으로 권하는 범위 (가정). 중간 배전도는 두 이웃 범위 사이로 정한 값 (가정). 우리 기록: 미디엄 B02는 96 °C에서 쓴맛이 강했고 92 °C가 좋았음 |
   | 붓기 나누기 | 뜸은 원두의 2배를 0초에 붓는다. 나머지 물은 **붓기마다 원두의 2·3·4배**로 나누는 모든 방법을 후보로 둔다(큰 붓기 먼저). 예: 8배 = 2-4-2, 2-3-3, 2-2-2-2. 양은 배수 × 원두 무게(1 g 단위) | 사용자가 레시피를 '원두의 몇 배'로 정하는 방식(예: 2-4-2, 2-4-3, 2-3-3-3)을 따름. 원두 무게가 바뀌어도 배수 모양이 그대로 유지된다 (10/19) |
   | 붓기 간격 | 평소 레시피의 간격을 그대로 쓴다(B02 30초, B01 60초) | 붓는 시각이 맛에 주는 효과는 모델도 우리 기록도 판단할 수 없어서, 후보로 바꾸지 않는다 (10/19) |

2. **분쇄 정하기:** 후보마다 추출수율이 목표와 같아지는 대표 크기를 찾는다. 곱게 갈수록 추출수율이 오르므로(성질 테스트 ①) 하나로 정해진다. 핸드드립 범위(약 700–1800 µm)를 벗어나는 후보는 뺀다.
   **막힘 한계:** 같은 원두의 기록 중 `막힘` 표시가 있는 잔이 있으면, 막혔던 가장 굵은 대표 크기보다 고운 분쇄는 후보에서 뺀다. 모델은 막힘을 예측하지 못하므로(7절), 막힘이 일어나는 분쇄 크기에서 직접 막는다. 맛 점수만으로는 부족하다. 점수가 낮은 잔은 목표를 당기지 않을 뿐 밀어내지는 않고, 모델이 막힌 잔의 위치를 실제와 다르게 계산하기 때문이다. 기록이 없는 새 원두는 기본 범위를 쓴다.
3. **가수량 정하기:** 가수는 추출수율을 바꾸지 않고 농도만 바꾸므로(식 12), `가수량 = 음료로 나간 성분 ÷ 목표 농도 − 음료 무게`로 정한다. 가수 없이도 목표보다 묽은 후보는 뺀다.
4. **고르기:** 남은 후보 중 목표에 가장 가까운 것을 고른다. 비슷하면 물 빠짐이 2:00–3:30 안인 것, 그다음 평소 레시피와 덜 다른 것을 고른다.
   - **구현 (10/19):** 남은 후보는 모두 분쇄와 가수량으로 목표를 맞추므로 '목표에 가까운 정도'는 같다. 그래서 실제로는 '끊김이 2:00–3:30 안 → 평소와 덜 다름' 순서로 고른다.
   - **평소 레시피:** 같은 원두의 마지막 정상 잔(물 비율, 온도, 붓기 배수와 간격). 기록이 없는 원두는 **같은 배전도 묶음**의 마지막 정상 잔에서 물 비율·붓기를 가져온다. 묶음은 중강배전(미디엄 다크) 이상과 그 밖(라이트~미디엄) 둘이다. 그 묶음에 기록이 없으면 사용자의 평소 두 레시피를 쓴다. 중강배전 이상은 B01 방식 1:8, 2-4-2배 / 60초, 그 밖은 B02 방식 1:11, 2-3-3-3배 / 30초다 (10/19). 온도는 그 원두 배전도 범위의 가운데로 둔다. 다른 원두의 온도는 배전도가 달라 그대로 쓰지 않는다.
   - **덜 다름:** `|물 비율 차이| + |온도 차이| ÷ 2 + 붓기 배수 차이 ÷ 2`. 붓기 배수 차이는 같은 자리 붓기끼리의 배수 차이를 더한 값(짧은 쪽은 0배로 채움)이다. 예: 평소 2-3-3-3과 후보 2-4-3-2는 차이 2. 물 비율 1배, 온도 2 °C, 붓기 한 자리 2배 변화를 같은 크기로 본다 (가정).
   - 계산을 줄이려고 후보를 '덜 다름' 순서로 계산하고, 끊김이 2:00–3:30 안인 첫 후보에서 멈춘다. 모두 계산해서 고르는 것과 결과가 같다. 범위 안인 후보 없이 범위 밖 후보만 30개 쌓이면 더 찾지 않고 그중 가장 덜 다른 후보를 고른다(모두 계산하면 30초 가까이 걸려서).
   - 분쇄 크기는 10 µm 단위로 맞추고(막힘 한계 안쪽으로 들어가면 한 칸 굵게), 그 크기로 가수량을 다시 계산한다. 조건을 만족하는 후보가 하나도 없으면 뺀 이유별 후보 수를 알려 준다.
5. **보여 주기:** 원두·물 양(비율), 온도, 붓기 일정(언제 몇 g), 분쇄 대표 크기(µm), 가수량과 함께 예상 물줄기 끊김 시각, 음료 무게, 추출수율, 농도를 보여 준다.

**모델이 정하지 않는 것:** 붓는 방식(센터 푸어, 원형 푸어, 붓는 높이, 물줄기 굵기)은 사용자에게 맡긴다. 모델은 드리퍼 안 물을 고루 섞인 하나의 통으로 보아서 이런 공간적인 차이를 계산하지 못한다. 대신 평소 붓는 습관이 물 빠짐에 주는 효과는 흐름 저항 보정(5절)에 저절로 들어간다. 붓기 일정이 향·단맛에 주는 효과도 모델에 없다(조사 노트 5·6). 그래서 붓기 모양은 평소 쓰던 몇 가지 안에서만 고른다.

### 9.3 분쇄는 µm로 추천하고 사진으로 확인한다

- 분쇄는 그라인더 클릭이 아니라 **대표 크기(µm)**로 추천한다. 클릭으로 바꾸려면 사용자가 여러 클릭에서 사진을 미리 찍어 둬야 해서, 처음 쓰는 사람도 바로 추천을 받는다는 장점이 약해진다.
- 사용자가 평소 감대로 간 뒤 분쇄도 탭에서 사진을 찍으면, 목표와 얼마나 다른지 보여 준다. 예: "1262 µm, 목표보다 48 µm(약 4%) 고와요 → 조금 더 굵게"
- **클릭은 시작점 힌트로만 함께 준다 (10/19).** 추천은 여전히 µm이다. 사용자가 '한 잔 내리기' 흐름에서 "몇 클릭으로 갈면 되는지"를 원해서, 정확한 환산이 아니라 시작점으로만 알려 주기로 했다. 순서는 아래와 같다.
  1. 같은 봉투를 같은 그라인더로 잰 기록이 있고 목표와 60 µm(사진 측정의 흔들림 ±5% 정도) 안이면, 그 잔의 클릭에서 1클릭당 크기 변화만큼 옮긴다. 1클릭당 변화는 한 봉투를 여러 클릭으로 잰 기록에서만 구한다. 같은 원두라도 봉투가 바뀌면 같은 클릭에서 크기가 달라서(95클릭: 1255 → 1044 µm) 다른 봉투 기록은 쓰지 않는다.
  2. 없으면 인터넷 클릭표(메버릭, `data/reference/maverick_click_table.csv`)로 알려 준다. 사진 측정과 기준이 달라 대략이라고 밝힌다. 우리 사진에서는 85 → 105클릭에 84 µm만 달라, 클릭표(같은 20클릭에 200 µm)보다 변화가 작다.
  3. 클릭표도 없는 그라인더는 가장 가까운 기록에서 방향(더 곱게/더 굵게)만 알려 준다.
- 갈고 나서 사진으로 실제 크기를 재고, 목표와 다르면 그 가루에 맞게 레시피를 바꾼다(한 잔 내리기 3단계, 보정 뒤 구현). 그 잔을 기록하면 클릭과 사진 크기가 함께 남아, 다음에 같은 봉투를 내릴 때는 내 기록으로 힌트를 준다. 쓸수록 사용자의 그라인더와 원두에 맞춰진다.

### 9.4 한계

- 점의 위치는 모델 추정값이라, 모델이 틀리면 선호 영역도 함께 틀릴 수 있다. 다만 모든 잔을 같은 모델로 계산하므로 잔끼리의 상대적인 위치는 쓸 만하다.
- 맛 점수는 한 사람이 블라인드 없이 매긴 값이다.
