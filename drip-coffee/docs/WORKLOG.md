### 2026-10-12 (저녁) — 원두 B02 첫 추출, 기준 온도와 맛 기록 방식 변경

  - 가수 전에 한 모금 먼저 마셔 보고 전후 차이를 메모함. 이번 잔은 가수하니 쓴맛은 줄었지만 바디감도 줄었음. 종합 점수 칸도 검토했지만 6항목과 겹쳐서 넣지 않음

### 2026-10-12 (밤) — 기능 2: 추출 모델 구현
- 한 일: 성질 테스트 9개를 먼저 커밋하고(d73d151), 추출 모델(`dripcoffee/extraction_model.py`)을 구현해 모두 통과시킴. 레시피와 분쇄도를 넣으면 0.5초 간격으로 붓기 → 물 흐름 → 추출 → 음료를 계산해 물 빠짐 시각, 음료 무게, 추출수율, 가수 전후 농도를 냄
- 문제 → 대응:
  - 테스트 ④(원두를 더 넣으면 늦게 빠짐)를 정하다가, 설계한 흐름 저항 식에 가루층 길이가 빠진 것을 찾음. 이대로면 원두를 늘릴 때 머금는 물만 늘어 오히려 빨리 빠지는 결과가 나옴 → 저항이 원두 무게에 비례하도록 넣음 (다르시: 저항 ∝ 층 길이)
  - 처음 정한 추출 속도(Moroney 거친 분쇄 값)로는 기준 레시피 추출수율이 약 11.5%로, 문헌 드립 데이터(16–24%)보다 낮음 → 같은 조사 범위 안의 카페인 실험값으로 바꾸니 약 18%. 카페인이 전체 성분보다 빨리 나올 수 있다는 점은 한계로 남김
  - 아주 고운 분쇄(400 µm)에서는 물 빠짐이 15분을 넘어 계산이 멈춤 → 15분은 계산을 멈추는 안전장치였을 뿐이라 1시간으로 늘리고, 고운 쪽 예측이 지나치게 긴 점은 한계로 적음

- 확인: 테스트 56개 통과(성질 테스트 14개 포함), 보류 2개

### 2026-10-15 — 교수님 피드백 대응: 추천 목표를 '내 선호 영역'으로
- 피드백 (10/12, 주제 설명에 대한 답): 좋은 주제지만, Claude나 ChatGPT에게 원두 사진을 올리고 "알맞은 레시피를 추천해 줘"라고 묻는 것 이상의 개성과 특별함이 무엇인지 생각해 보라는 내용
- 검토: 범용 AI는 분쇄를 말로 추측하고, 업계 평균 레시피를 주고, 대화가 끝나면 잊는다. 우리 도구는 분쇄를 µm로 재고, 내 장비의 물 빠짐·음료 무게로 모델을 맞춘다. 하지만 추천 목표를 골든컵(업계 평균)으로 두면 결과가 결국 일반론과 비슷해진다는 약점을 찾음. 커피는 본질적으로 기호식품이라 '좋은 한 잔'의 기준이 사람마다 다르고, 골든컵은 많은 사람이 대체로 좋아하는 범위일 뿐임. 실제로 같은 원두에서도 96 °C 잔은 별로, 92 °C 잔은 좋았음
- 검토한 후보와 결정:
  - A. 내 선호 영역 → **넣음.** 잔마다 모델이 계산한 (추출수율, 농도) 위치를 맛 점수로 가중해 내 선호 중심을 찾고, 추천 목표를 골든컵에서 내 선호 쪽으로 옮겨 감. 기록이 적을 때는 골든컵에 가깝게 섞어서, 처음 쓰는 사람도 추천을 받음 (MODEL.md 9절)
  - B. 그라인더 클릭으로 답하기 → **바꿈.** 클릭 환산을 하려면 사용자가 여러 클릭에서 사진을 미리 찍어 둬야 해서 '처음부터 바로 추천'의 의미가 약해짐. 분쇄는 µm로 추천하고, 간 뒤 사진으로 목표와 비교하는 것까지만 함
  - C. 뜸 실험 → **시간이 남으면.** 핸드드립 뜸 효과를 잰 동료 심사 연구가 없어서 우리 기록이 새로운 데이터가 됨. B01로 4잔 설계만 정해 둠 (BREW_PROTOCOL)
- 바뀐 범위: 맛 점수의 역할이 '기록·참고용'에서 '추천 목표를 정하는 값'으로 바뀜 (CLAUDE.md). 계획에서 보류했던 '맛 취향 학습 추천'을 머신러닝 없이 가중 평균으로 가볍게 넣는 셈
- 정한 값: 골든컵과 섞는 비율 5, 가중치 기준 2.5점은 문헌 값이 아니라 정한 값이라 '가정'으로 표시함
